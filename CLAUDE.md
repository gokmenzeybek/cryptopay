## Project Overview

CryptoPay is an XRPL (XRP Ledger) payment application that combines a React frontend with an Express.js backend. The application enables wallet creation, XRP payments, QR code generation/scanning, transaction tracking, and **peer-to-peer TRY-to-XRP conversions** on the XRPL testnet.

**Current Version: 3.0.0** - Features PostgreSQL database, Docker deployment, and enhanced P2P exchange system.

**Key Architecture:**
- **Frontend**: React application (in `src/`) with React Router and styled-components
- **Backend**: Express.js server (`server.js`) with PostgreSQL database
- **XRPL Integration**: Connects to XRPL testnet (`wss://s.altnet.rippletest.net:51233`)
- **P2P TRY Conversion**: Peer-to-peer Turkish Lira to XRP exchange without third-party providers (v3.0)
- **Database**: PostgreSQL with persistent storage and Data Access Layer (DAL)
- **No Third-Party Providers**: Direct user-to-user matching without Stripe/PayPal/MoonPay
- **Turkish Payment Methods**: Supports Bank Transfer, Papara, İninal, Mefete, QR Havale
- **Docker Support**: Full containerization with docker-compose for easy deployment
- **Local Network Support**: Designed to work across devices on the same local network

## Architecture Details

### Frontend Architecture (`src/`)

**Component Structure:**
- `App.js` - Main app component with React Router setup
- `hooks/useXRPL.js` - Custom hook and context provider for XRPL operations (wallet management, payments, balance tracking)
- `components/` - React components for each feature:
  - `Wallet.js` - Wallet creation and display
  - `Payment.js` - Send XRP payments
  - `RequestPayment.js` - Generate payment request QR codes
  - `QRScanner.js` - Scan QR codes using device camera
  - `Dashboard.js` - View transaction history and statistics
  - `Header.js` - Navigation header

**Key Frontend Concepts:**
1. **XRPLProvider Context**: Wraps the entire app to provide XRPL client, wallet state, and transaction methods
2. **Dynamic API URL**: Frontend automatically detects if accessed via localhost or network IP and adjusts API base URL accordingly
3. **XRPL Library Loading**: Uses CDN-loaded `xrpl.js` library (window.xrpl), requires waiting for library to load before operations
4. **Transaction Validation**: Uses `waitForValidation()` helper to ensure transactions are confirmed on the ledger

### Backend Architecture

**Server Structure (`server.js`):**
- Express server with CORS enabled for cross-origin requests
- Serves static React build files from `build/` directory
- Provides REST API endpoints for data persistence and sharing across devices
- Catches all routes (`app.get('*')`) to serve React app for client-side routing

**PostgreSQL Database:**

- **Transactions Table**: Complete transaction history with XRPL transaction data
- **Payment Requests Table**: QR payment request management
- **P2P Orders Table**: P2P TRY-XRP exchange orders and matching
- **Data Access Layer (DAL)**: Organized database operations in `database/dal/`
- **Connection Pooling**: Efficient database connection management
- **Schema Migrations**: Version-controlled database schema updates

**Database Architecture (`database/`):**

## XRPL Integration Patterns

### Wallet Operations
```javascript
// Connect to XRPL testnet
const client = new window.xrpl.Client("wss://s.altnet.rippletest.net:51233");
await client.connect();

// Create and fund wallet
const wallet = window.xrpl.Wallet.generate();
const fundResult = await client.fundWallet(wallet);

// Load existing wallet from seed
const wallet = new window.xrpl.Wallet(seed);
```

### Transaction Pattern
```javascript
// 1. Prepare payment
const payment = {
  TransactionType: "Payment",
  Account: wallet.address,
  Amount: window.xrpl.xrpToDrops(amount.toString()),
  Destination: recipientAddress,
  Memos: [{ Memo: { MemoData: window.xrpl.convertStringToHex(memo) } }]
};

// 2. Autofill (adds Fee, Sequence, etc.)
const preparedTx = await client.autofill(payment);

// 3. Sign
const signedTx = wallet.sign(preparedTx);

// 4. Submit and validate
const prelim = await client.submit(signedTx.tx_blob);
if (prelim.result.engine_result !== 'tesSUCCESS') throw error;

// 5. Wait for ledger validation
const validated = await waitForValidation(client, signedTx.hash);
```

### Error Handling
- Always check `engine_result` for preliminary submission
- Always validate transaction using `tx` command before considering complete
- Handle account_info errors to detect invalid addresses

## P2P TRY-XRP Exchange System (v3.0)

### Overview
The application now supports peer-to-peer Turkish Lira (TRY) to XRP conversions without requiring third-party payment providers. Users directly match with each other and transfer TRY via Turkish payment methods.

### Key Features
1. **No Third-Party Providers**: Direct P2P matching without Stripe, PayPal, or MoonPay
2. **Turkish Payment Methods**: Bank Transfer, Papara, İninal, Mefete, QR Havale
3. **Web Scraping Rates**: Real-time XRP/TRY rates from BTCTurk, Paribu, Binance, CoinGecko
4. **Smart Matching**: Reputation-based order matching (rating, completed trades)
5. **Order Lifecycle**: OPEN → MATCHED → PAYMENT_CONFIRMED → COMPLETED
6. **Dispute System**: Built-in dispute handling for problematic trades
7. **Rate Caching**: Caches rates for 5 minutes to reduce API calls
8. **Weighted Averaging**: Turkish exchanges weighted higher (BTCTurk: 1.5x, Paribu: 1.5x)

### Typical P2P Trading Flow

**For Buyers (Want to buy XRP with TRY):**
1. Check current XRP/TRY rate from scraped sources
2. Create buy order with desired amount, rate, and payment methods
3. Browse available sell orders or wait for matches
4. Match with a seller
5. Transfer TRY via agreed payment method (Papara, Bank, etc.)
6. Confirm payment sent
7. Receive XRP from seller to XRPL address
8. Trade completed

**For Sellers (Want to sell XRP for TRY):**
1. Create sell order with XRP amount, desired rate, and payment methods
2. Wait for buyer to match
3. Receive TRY payment notification and verify
4. Confirm TRY payment received
5. Transfer XRP to buyer's XRPL address
6. Submit XRPL transaction hash to complete trade

### Order Statuses
- `OPEN` - Order active, looking for matches
- `MATCHED` - Found counterparty, awaiting payment
- `PAYMENT_CONFIRMED` - TRY payment confirmed, awaiting XRP
- `COMPLETED` - Both TRY and XRP transferred successfully
- `CANCELLED` - Order cancelled before matching
- `EXPIRED` - Order expired without match (default: 30 minutes)
- `DISPUTED` - Dispute raised during transaction

### Rate Scraping Sources
| Source | Type | Weight | Notes |
|--------|------|--------|-------|
| BTCTurk | Turkish Exchange | 1.5x | Direct XRP/TRY pair |
| Paribu | Turkish Exchange | 1.5x | XRP_TL pair |
| Binance | International | 1.2x | XRP/USDT × USDT/TRY |
| CoinGecko | Aggregator | 1.0x | Free API, no key |
| P2P Market | Internal | 1.3x | Current open orders |
| P2P Completed | Internal | 1.8x | Recent completed trades |

### Security & Best Practices
1. **For Buyers**: Check seller reputation, keep payment proof, verify XRP transaction
2. **For Sellers**: Confirm TRY payment before sending XRP, use trusted payment methods
3. **Dispute Resolution**: Raise disputes immediately with evidence (screenshots, transaction IDs)
4. **Start Small**: Begin with small amounts for new counterparties
5. **Escrow**: Consider implementing escrow mechanism for production use
